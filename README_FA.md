# نسخهٔ ماژولار CNC / OptiCut

این پوشه نسخهٔ جداگانهٔ برنامه است. فایل اصلی و آزمون‌های ریشهٔ پروژه تغییر نکرده‌اند. قواعد برش، تلورانس‌ها و قالب DXF از نسخهٔ فعلی منتقل شده‌اند.

## اجرای برنامه

از داخل این پوشه، در PowerShell 7:

```powershell
./Invoke-Cnc.ps1 -ValidateOnly
./Invoke-Cnc.ps1 -SourceFolder ./tests/Sample_A_Valid -OutputFolder ./Output -ValidateOnly
./Invoke-Cnc.ps1 -SourceFolder ./tests/Sample_A_Valid -OutputFolder ./Output
```

می‌توانید `Run-Cnc.cmd` را هم اجرا کنید. این اجراکننده از PowerShell قابل‌حمل در پوشهٔ والد استفاده می‌کند. برای انتقال مستقل، PowerShell 7 نصب کنید و فایل PS1 را اجرا کنید.

**هشدار: اجرای عادی، بعد از تأیید ورودی‌ها و پیش از ذخیرهٔ خروجی، تمام محتوای پوشهٔ خروجی را پاک می‌کند.** پیش‌فرض ورودی `Desktop/A` و خروجی `Desktop/B` است. حالت `ValidateOnly` خروجی نهایی را ذخیره نمی‌کند؛ فایل‌های موقت برای بررسی مجدد DXF ایجاد و پاک می‌شوند. از پوشهٔ اختصاصی برای خروجی استفاده کنید.

## تقسیم مسئولیت‌ها

| فایل در src | مسئولیت |
|---|---|
| Dxf.ps1 | خواندن DXF، کدهای گروه، متن‌ها، لایه‌ها و نوشتن موجودیت‌ها |
| Rules.ps1 | دستور زبان SH/Z، اندازه‌ها، جدول‌ها و جهت عملیات |
| Geometry.ps1 | مستطیل، حدود، رأس بریدگی و کنترل تداخل و ایمنی هندسه |
| OptiCut.ps1 | تشخیص قالب Legacy/Layered، اتصال متن به قطعه و ساخت طرح اولیه |
| Planning.ps1 | جفت‌سازی قطعات در چند فایل و تعیین نقش و جهت نهایی |
| Generation.ps1 | اعمال طرح، تولید خطوط DXF و بررسی خروجی بازخوانی‌شده |
| Pipeline.ps1 | رابط پردازش دسته‌ای در حافظه و قرارداد مستقل JSON |
| Application.ps1 | مسیرها، پیام‌ها، اعتبارسنجی دسته‌ای، ذخیره و مدیریت فایل‌ها |

`Cnc.psm1` نقطهٔ بارگذاری است. اجزا در محدودهٔ داخلی همین ماژول بارگذاری می‌شوند؛ برای هر اجرا هیچ تابعی از متن برنامه استخراج نمی‌شود. وابستگی پنهان توابع به متغیرهای فرهنگ عددی و تلورانسِ فراخواننده حذف شده است. تلورانس‌های قبلی ۰٫۰۵ و ۰٫۱ میلی‌متر به‌صورت محلی حفظ شده‌اند.

## رابط پردازش در حافظه

```powershell
Import-Module ./Cnc.psm1 -DisableNameChecking
$documents = @(Get-ChildItem ./tests/Sample_A_Valid/*.dxf |
    Sort-Object Name | ForEach-Object { Read-DxfDocument $_ })
$plans = New-CncBatchPlan -Documents $documents
$contract = ConvertTo-CncPlanContract -Documents $plans
$outputs = ConvertTo-CncOutput -Documents $plans
```

ساخت طرح و تولید خطوط در حافظه انجام می‌شوند. خواندن ورودی و بررسی بازخوانی خروجی، همچنان مسئولیت بخش DXF است. توابع قدیمی جهت آزمون و انتقال تدریجی صادر شده‌اند؛ رابط پیشنهادی برای مصرف جدید همین چهار تابع و `Invoke-CncBatch` است.

**طرح‌ها تغییرپذیرند:** برنامه‌ریزی و تولید، اشیای ورودی را تغییر می‌دهند. برای اجرای دوباره، اسناد را از نو بخوانید. قرارداد JSON یک تصویر جدا از طرح است و به اشیای داخلی ارجاع ندارد؛ آن را پیش از تولید دریافت کنید.

## مسیر مهاجرت به زبان دیگر

برای گرفتن طرح قابل‌مقایسه، بدون تولید فایل CNC:

```powershell
./Export-Plan.ps1 -SourceFolder ./tests/Sample_A_Valid > plan.json
```

پیام‌های تشخیصی این فرمان از خروجی JSON حذف می‌شوند. قرارداد نسخهٔ ۱ شامل واحد `mm`، نام و قالب فایل، شناسهٔ قطعه، برچسب، محدودهٔ هندسی، جدول، نقش و جهت، مشخصات شیار و بریدگی است. مقدار عملیات غایب `null` است و مجموعه‌های files و operations همیشه آرایه‌اند.

این JSON برای تبادل و مقایسهٔ **تصمیم‌های CNC** است؛ بازسازی کامل DXF از آن پشتیبانی نمی‌شود و برنامه نیز فعلاً آن را به‌عنوان ورودی نمی‌خواند. اطلاعات کامل موجودیت‌ها و سربرگ DXF در مدل داخلی باقی می‌مانند.

ترتیب پیشنهادی مهاجرت:

1. تحلیل برچسب و جدول قواعد را منتقل کنید؛ آزمون‌های مثبت و منفی فعلی معیار باشند.
2. هندسه را با همان واحد، تلورانس، گردکردن سه‌رقمی و ترتیب رأس‌ها منتقل کنید.
3. تشخیص OptiCut و جفت‌سازی بین فایل‌ها را منتقل و JSON تصمیم‌ها را مقایسه کنید.
4. خواندن/نوشتن DXF را منتقل و خروجی را با فایل‌های مرجع مقایسه کنید.
5. در پایان رابط اجرا و مدیریت فایل‌ها را جایگزین کنید.

این بازآرایی هنوز از اشیای PowerShell و ساختار تغییرپذیر قبلی استفاده می‌کند؛ تبدیل خودکار به زبان دیگر نیست. مرز فایل‌ها، رابط پردازش و JSON، نقاط شروع مشخصی برای مهاجرت فراهم می‌کنند. بعضی توابع دامنه پیام تشخیصی Write-Host دارند؛ برای رابط کتابخانه‌ای زبان جدید بهتر است این پیام‌ها به گزارش‌دهندهٔ جدا منتقل شوند.

## آزمون‌ها

```powershell
./tests/Run-Tests.ps1
```

آزمون‌های برچسب، هندسه و OptiCut ماژول را مستقیم بارگذاری می‌کنند. داده‌های آزمون داخل همین پوشه کپی شده‌اند. آزمون Parity تنها برای مقایسه با نسخهٔ اصلی به فایل اصلی در پوشهٔ والد نیاز دارد؛ این آزمون هر دو نسخه را با ورودی تازه اجرا می‌کند و تمام خطوط خروجی DXF را مقایسه می‌کند. هیچ آزمونی به Desktop/A یا Desktop/B نمی‌نویسد.

نکتهٔ رفتار نسخهٔ قبلی: پاک‌سازی خروجی قبل از مرحلهٔ ذخیره رخ می‌دهد؛ سازوکار پشتیبانِ مرحلهٔ ذخیره نمی‌تواند محتوایی را که در پاک‌سازی اولیه حذف شده برگرداند. این رفتار در نسخهٔ جدید حفظ شده است. کنترل اضافی مسیر، استفاده از ریشهٔ درایو، پوشهٔ ورودی، والد ورودی یا junction/symlink به‌عنوان خروجی را رد می‌کند.
